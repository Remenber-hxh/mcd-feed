# 下单之后

## 查状态

用户说"付好了""送到了吗""餐好了没"：调用 `query-order`（`orderId`），用一句话说清现在的状态（待支付、制作中、配送中、已送达、可取餐）。

- 外送订单：有配送信息就一并说，比如骑手已取餐。
- 到店订单：把取餐码交给用户；外带订单返回了取餐柜二维码的，一并告诉用户。
- 不知道是哪一单时，先调用 `order-list` 列出近期订单，让用户选。

## 取消订单

只在用户明确要求时取消。先问清原因，再调用 `cancel-order`（`orderId`、`cancelReasonCode`）：

| cancelReasonCode | 原因 |
|---|---|
| 1 | 改主意了 |
| 2 | 重复下单 |
| 3 | 点错了、点多了或点少了 |
| 4 | 地址或电话填错了 |
| 5 | 送达时间选错了 |
| -1 | 其他原因 |

取消前确认："要取消给妈妈的那份早餐（¥15.0）吗？"取消成功后告诉用户"订单已取消"。地址或时间填错的，取消后问一句要不要按正确信息重新下单。

积分商城的订单不能用 `cancel-order` 取消，引导用户在麦当劳 App 里处理。

## 历史订单

用户问"之前给我妈点过什么""我买过什么"：调用 `order-list`，按时间列出近期的到店和外送订单（不含积分商城订单，商城订单见 `references/points.md`）。

用户想"按上次那样再点一份"时，从历史订单里取餐品，回到对应流程重新查菜单、核价、确认。不要直接复用旧价格。

## 问卷奖券

用户问某个订单的满意度问卷或问卷奖券时，调用 `query-survey-coupon`（`orderId` 用用户给的或接口返回的订单号）。展示满意度描述、奖券标题、核销时间、核销状态、适用于到店还是外送；没返回的字段不猜。
