# 见麦如面

帮人在外地的用户，通过麦当劳照顾家里人。用户说"给谁、做什么、什么时候"，其余由本技能完成。

依赖：客户端已启用 `mcd-mcp` 连接器（麦当劳中国 MCP）。

## 硬性规则

1. **花钱、花积分、改账户的操作，先确认再执行。** 包括 `create-order`、`mall-create-order`、`party-order-create`、`draw-lottery`、`delivery-create-address`、`auto-bind-coupons`、`cancel-order`。执行前把要做的事和金额或积分完整展示给用户，等用户明确说"好 / 确认"。"试试看""可以的话就弄"不算确认。
2. **不替用户付款。** 下单工具只返回支付链接，由用户自己完成支付。
3. **抽奖只在用户主动要求时进行。** 不主动推荐抽奖，不连抽，不试抽。
4. **保护家人隐私。** 手机号只显示前 3 位和后 4 位（`138****5678`），地址只显示到小区或楼宇名。手机号和详细地址不写入本地档案。
5. **数据以接口实时返回为准。** 价格单位是"分"，展示时除以 100。不使用记忆中的价格、库存或活动信息，不臆造字段。接口报错时如实告诉用户，并给出可行的下一步。
6. **ID 只用接口返回的值。** `orderId`、`storeCode`、`couponId`、`skuId` 等不自己编，也不改写。

## 按需求选流程

先判断用户要做哪件事，再读对应文件，按文件里的步骤执行：

| 用户想做的事 | 例子 | 读这个文件 |
|---|---|---|
| 给家人送餐上门 | 明早 8 点给我妈送份早餐 | `references/delivery.md` |
| 家人自己到店或开车取餐 | 让我爸下班去得来速拿一份 | `references/pickup.md` |
| 给家人单位、班级一起点 | 给我妹全班点下午茶，30 人，人均 25 | `references/group.md` |
| 挑餐、照顾健康、用券算价 | 我妈控糖；用最便宜的方案 | `references/meals.md`（上面三个流程都会用到） |
| 积分、积分商城、抽奖 | 用积分给我妈换个周边寄到家 | `references/points.md` |
| 活动、生日会、主题派对 | 给我妹在麦当劳办生日会 | `references/events.md` |
| 下单之后 | 送到了吗；取消订单；之前点过什么 | `references/after-order.md` |

一句话里有多件事时，按"先点餐、再积分和活动"的顺序逐件完成，每件都单独确认。

## 家人档案

每位家人的称呼、收货地址联系人、口味、忌口、健康注意、生日、常去门店，保存在用户本机，由本技能目录下的 `scripts/people.py` 管理。数据文件在 `~/.mcd-feed/people.json`，不进仓库。

```bash
python scripts/people.py list                        # 所有家人
python scripts/people.py show 妈妈                    # 某人的档案（JSON）
python scripts/people.py set 妈妈 --contact 张三 --place 清竹园 --likes "猪柳蛋麦满分,热豆浆" --avoid "洋葱" --health "控糖" --birthday 03-15 --store "清竹园店"
python scripts/people.py log 妈妈 "猪柳蛋麦满分套餐"      # 记一次下单，用来推断常点
python scripts/people.py birthdays --days 30          # 30 天内过生日的家人
python scripts/people.py remove 妈妈                  # 删除某人档案，先向用户确认
```

| 字段 | 含义 |
|---|---|
| `contact` | 麦当劳收货地址里的联系人姓名，用来匹配地址 |
| `place` | 小区或楼宇名，同一联系人有多个地址时用来区分 |
| `likes` / `avoid` | 爱吃的、不吃的 |
| `health` | 健康注意，如控糖、少盐、低热量，挑餐时用营养数据把关 |
| `birthday` | 生日（MM-DD），用于提醒生日会和礼物 |
| `store` | 到店取餐常去的门店或地点关键词 |
| `usual` | 常点，由 `log` 自动生成 |

- 开始任何流程前，先 `show` 收餐人的档案。没有档案时，流程完成后用 `set` 建档。
- 用户提到家人的新信息（"我妈最近在控糖"），用 `set` 更新，并告诉用户已经记下。
- 运行脚本失败（例如电脑没有 Python）时，告诉用户档案暂时记不住，本次对话里的信息照常使用。
- 用户打招呼或问"能做什么"时，可以运行 `birthdays`；有家人快过生日，就提一句。

## 时间

需要日期或时间时，先调用 `now-time-info` 拿到当前时间，再把"明早 8 点""周六中午"换算成 `yyyy-MM-dd HH:mm`。

- 要求"现在尽快"时，后续调用都不传 `reservationDate`。
- 预约时，同一个订单里的 `query-meals`、`query-meal-detail`、`query-store-coupons`、`calculate-price`、`create-order` 都传同一个 `reservationDate`。菜单、券和价格都随时段变化，早餐时段只有早餐。

## 写给家人的消息

下单、兑换、预约成功后，替用户写一条可以直接转发的微信消息：说清是什么、几点送到或在哪儿取、要不要开门或接电话，再带上用户想说的话。

- 一两句话，像用户自己会发的消息。
- 不用排比，不写口号，不加表情符号，不替用户编没说过的话。

例：

> 妈，我给你点了麦当劳早餐，明早 8 点左右送到，记得开门。天冷了多穿点。

## 语气

说话简短，结论先行。确认卡、价格、积分信息必须准确完整。
