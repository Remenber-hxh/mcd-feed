# 见麦如面

帮人在外地的用户给家里人点麦当劳外送（麦乐送）。用户只说"给谁、什么时候、想说什么"，其余由本技能完成。

依赖：已在客户端启用 `mcd-mcp` 连接器（麦当劳中国 MCP）。本技能只用麦乐送场景：`beType=2`、`orderType=2`。

## 硬性规则

1. **下单前必须确认**。调用 `create-order` 之前，把确认卡（见第 8 步）完整展示给用户，等用户明确说"好 / 确认 / 下单"。用户没确认，不下单。
2. **不替用户付款**。`create-order` 只返回支付链接，由用户自己完成支付。
3. **不主动取消订单**。只有用户明确要求时才调用 `cancel-order`。
4. **保护收餐人隐私**。展示手机号时只显示前 3 位和后 4 位（`138****5678`）；地址只显示到小区或楼宇名。手机号不写入本地档案。
5. **价格以接口实时返回为准**。`calculate-price` 返回单位是"分"，展示时除以 100。不使用记忆中的价格。
6. **字段以接口实际返回为准**。不臆造不存在的字段；接口报错时如实告诉用户，并给出可行的下一步。

## 收餐人档案

每个收餐人的称呼、对应的麦当劳收货地址、口味、忌口保存在用户本机，由本技能目录下的 `scripts/people.py` 管理（数据文件在 `~/.mcd-feed/people.json`，不进仓库）：

```bash
python scripts/people.py list                     # 列出所有收餐人
python scripts/people.py show 妈妈                 # 查看某人档案（JSON）
python scripts/people.py set 妈妈 --contact 张三 --place "清竹园" --likes "猪柳蛋麦满分,热豆浆" --avoid "洋葱,辣"
python scripts/people.py log 妈妈 "猪柳蛋麦满分套餐"   # 记录一次下单
```

- `--contact`：麦当劳收货地址里的联系人姓名，用来在 `delivery-query-addresses` 的结果里找到这个人的地址。
- `--place`：地址里的小区或楼宇名，同名联系人有多个地址时用来区分。
- `--likes` / `--avoid`：爱吃的、不吃的，逗号分隔。
- `log` 会把这次点的餐记进"常点"，下次优先推荐。

## 工作流程

### 第 1 步：听懂需求

从用户的话里提取四件事，缺的再问，一次只问一个：

| 要素 | 例子 | 缺了怎么办 |
|---|---|---|
| 收餐人 | 妈妈、对象、小王 | 必须问 |
| 送达时间 | 现在、明早 8 点、今晚 10 点 | 默认"现在尽快送" |
| 想吃什么 | 早餐、汉堡、"老样子" | 按档案推荐 |
| 想说的话 | "天冷了多穿点" | 可以没有 |

### 第 2 步：读档案

运行 `python scripts/people.py show <称呼>`。

- 有档案：拿到 `contact`、`place`、`likes`、`avoid`、`usual`。
- 没有档案：进入第 4 步的"新建地址"流程，下单成功后再用 `set` 建档。

### 第 3 步：确定时间

调用 `now-time-info` 拿到当前时间，把用户说的时间换成 `yyyy-MM-dd HH:mm`（例如"明早 8 点"→ 明天的 `08:00`）。

- 要求"现在尽快送"时，后续调用**都不传** `reservationDate`。
- 预约时，后续的 `query-meals`、`query-meal-detail`、`query-store-coupons`、`calculate-price`、`create-order` **都传同一个** `reservationDate`。菜单会随时段变化（早餐时段只有早餐），所以必须带上。

### 第 4 步：找到收货地址

调用 `delivery-query-addresses`，返回列表在 `data.addresses[]`，每项有 `addressId`、`contactName`、`fullAddress`、`phone`。用档案里的 `contact` 匹配 `contactName`；同一联系人有多个地址时，再用 `place` 匹配 `fullAddress`，拿到 `addressId`。

找不到地址时，向用户收集以下信息，复述确认后调用 `delivery-create-address`：

- 城市（如"南京市"）、地址（小区或楼宇）、门牌号、联系人姓名、称谓（先生 / 女士）、11 位手机号

这些信息只用于在用户自己的麦当劳账户里新建收货地址，不写入本地档案（档案只记联系人姓名和小区名）。

### 第 5 步：找能送的门店

调用 `delivery-query-stores`（`addressId`，`beType=2`），取第一家可配送门店的 `storeCode` 和 `beCode`，后续都用这一家。

- 没有可配送门店：告诉用户"这个地址附近暂时没有能送的麦当劳"，建议换个时间再试。

### 第 6 步：挑餐

调用 `query-meals`（`storeCode`、`beCode`、`beType=2`、`orderType=2`，预约时带 `reservationDate`），按下面的顺序挑 1–3 个候选：

1. 用户点名要的；
2. 档案里的 `usual`（常点）和 `likes`；
3. 按时段给默认推荐：早上选早餐套餐，午晚餐选汉堡套餐，夜里选小份。

过滤掉含 `avoid` 的餐品。忌口能用特制解决的（比如"不要洋葱"），调用 `query-meal-detail` 查看 `modification`，按工具说明里的 key 规则传特制参数。

### 第 7 步：用券算最低价

1. 调用 `available-coupons`。有可领的券时问一句："有 N 张券可以领，要我顺手领了吗？"用户同意后调用 `auto-bind-coupons`。
2. 调用 `query-store-coupons` 拿到这家店、这个时段能用的券。
3. 对每个候选，分别用"不用券"和"用能用的券"调用 `calculate-price`，取实付最低的方案。

### 第 8 步：确认卡

用下面的格式展示，等用户确认：

```
下单确认
收餐人：妈妈（清竹园，138****5678）
送达：明天 08:00 左右
门店：XX 店
餐品：猪柳蛋麦满分套餐（不要洋葱）
价格：原价 ¥24.0 → 用券后 ¥15.0（含配送费 ¥X）
给骑手的备注：放门口，不用敲门
回复"好"就下单
```

- 备注（`remark`）最多 50 字，是给门店和骑手看的。用户想对收餐人说的话，放到第 10 步的消息里，不要写进备注。
- 用户要改（换餐品、改时间、去掉某样东西），回到对应步骤重新算价，再出确认卡。

### 第 9 步：下单

用户确认后调用 `create-order`：`addressId`、`storeCode`、`beCode`、`beType=2`、`orderType=2`、`items`（含 `couponId`/`couponCode`）、预约时的 `reservationDate`、`remark`、`needTableware`。

把返回的支付链接给用户，并说："付完回我'付好了'，我帮你看订单状态。"

### 第 10 步：写一条给收餐人的消息

下单成功后，替用户写一条可以直接转发的微信消息，带上送达时间和用户想说的话，语气按收餐人关系调整。例如：

> 妈，我给你点了麦当劳早餐，明早 8 点左右送到，记得开门。天冷了多穿点。

### 第 11 步：跟进和记账

- 用户说"付好了"或"送到了吗"：调用 `query-order` 查状态，用一句话说清楚（制作中 / 配送中 / 已送达）。
- 下单成功后运行 `python scripts/people.py log <称呼> "<餐品名>"`；第一次给这个人下单时，先用 `set` 建档。

## 语气

说话简短，结论先行。确认卡和价格信息必须准确、完整。

写给家人的消息要像用户自己会发的微信：一两句话，说清几点送到、要不要开门或接电话，再带上用户想说的话。不用排比、不写口号、不加表情符号，不替用户编造用户没说过的话。
